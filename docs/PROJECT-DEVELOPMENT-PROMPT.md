## 项目背景

`CreateTacZrecipe` 是面向 Mechanomania 1.21.1 NeoForge 实例的 TaCZ 自动化配方扩展项目。
项目主要使用 KubeJS、Create 及其附属模组提供的配方接口，为 TaCZ 弹药、枪械和配件建立可自动化生产的工艺链。

Arcana 的 NeoForge 移植属于同级目录下的独立项目 `ArcanaNeoForge`，除非任务明确要求，不要修改或合并它。

## 开发原则

1. 开始前先阅读现有 README、开发方案、接口文档、相关脚本和测试记录。
2. 优先复用当前整合包已经存在的模组、配方类型、标签和资源结构。
3. 保持项目与未来整合包更新的低耦合，不覆盖整套 KubeJS 或其他模组文件。
4. 只复制和修改本项目拥有的文件；枪包本体、加密资源和受许可证限制的文件不重新打包或分发。
5. 新增内容应尽量通过接口配置、数据文件、标签和资源文件表达，避免把枪包专属逻辑散落到多个脚本中。
6. 保持 `createtaczrecipe` 命名空间稳定；如确实需要改变公开 ID，先说明存档兼容影响。
7. 所有测试优先在 `Mechanomania11120-CreateTacZrecipe-Test` 中进行，禁止为了测试直接修改原始实例。

## 任务执行方式

- 先检查当前工作树和已有用户改动，不要覆盖或回退无关修改；
- 先完成只读分析，再进行最小范围实现；
- 对脚本做语法检查，对 JSON 做结构检查；
- 需要游戏验证时，执行启动、资源重载、JEI 配方显示、机械加工、成品装填/使用和退出测试中与任务相关的部分；
- 记录实际使用的实例、模组版本、测试步骤和结果；
- 若发现错误，优先从本次任务涉及的脚本、配方和资源排查，不要先修改无关模组；
- 完成后检查 Git 差异，写清提交内容，再提交并推送到对应远程仓库；
- 最终报告应列出修改文件、验证结果、已知限制和后续风险。

## 重要暂停条件

如果任务涉及以下尚未确定的设计方向，请停止实现并先与我讨论，不要自行拍板：

- 改变弹药品质的总体实现方式；
- 在独立 `AmmoId` 与自定义组件之间选择方案；
- 改变 TaCZ 原有工作台或枪包的公开配方；
- 选择新的中间物品、材料经济或产量平衡；
- 让机械手控制 TaCZ 工作台或其他非标准设备；
- 为特殊弹药增加命中、伤害、弹速、点燃、穿透等运行时效果；
- 需要新增 Java 模组、Mixin、事件注入或修改第三方模组行为；
- 删除、迁移或重命名已进入测试存档的公开物品/配方 ID；
- 需要下载、复制或重新分发枪包的加密资源；
- 任何会明显扩大项目范围、改变用户体验或影响原始整合包稳定性的方案。

遇到暂停条件时，请说明：

1. 已确认的事实；
2. 存在的技术选择；
3. 每种选择的影响；
4. 需要我决定的具体问题。

在我明确选择前，只进行分析、验证和必要的只读检查。

## 默认优先级

除非我另行指定，按以下顺序考虑工作：

1. 保持原始 Mechanomania 实例不受影响；
2. 保证现有 9mm 原型可启动、可重载、可显示、可加工和可使用；
3. 完善可编辑的枪包/弹药接口；
4. 验证品质弹药和特殊效果的可行性；
5. 扩展其他弹药口径；
6. 再研究枪械和配件的自动化装配。

不要因为某项未来功能尚未确定，就提前引入大型抽象、复杂依赖或不可逆的数据迁移。
