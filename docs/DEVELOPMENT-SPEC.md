# CreateTacZrecipe 开发方案

## 1. 项目定位

`CreateTacZrecipe` 是面向 Mechanomania 1.21.1 NeoForge 实例的 TaCZ 自动化配方扩展。
项目只提供配方、脚本、资源和兼容逻辑，不内置 TaCZ、枪包或受许可证限制的资源。
Arcana 的 NeoForge 移植属于旁边的 `ArcanaNeoForge` 项目，不在本项目中重复实现。

核心目标：

- 用 Create 的机械加工链替代部分 TaCZ 枪械和弹药的直接合成；
- 允许玩家通过接口文件自定义材料、工序、中间产物和成品；
- 为中间产物提供可替换的名称、贴图和模型；
- 保持与未来整合包更新的低耦合，避免覆盖整套 KubeJS 或枪包文件；
- 保留 TaCZ 原有工作台作为手动制作和兼容后备方案。

## 3. 弹药生产链

第一阶段以 9mm 为样板，目标链条为：

1. 制作 9mm 弹壳模具；
2. 用压铸/压模机加工黄铜材料，得到空弹壳；
3. 制作 9mm 弹头模具；
4. 用压铸/压模机加工铜材料，得到粗制弹头；
5. 用砂纸打磨粗制弹头，得到抛光弹头；
6. 用冲压机批量制作小型枪械底火；
7. 用混合机批量制作定量装药；
8. 用序列组装完成底火安装、装药、弹头安装和压合；
9. 输出带有 `AmmoId` 的 TaCZ 弹药物品。

中间产物用于解决机械手一次只加工一件物品的问题，也让每一步的材料消耗、产量和失败成本可以单独平衡。

## 4. 可配置接口

当前接口位于：

- `src/kubejs/server_scripts/createtaczrecipe/ammo_9mm.js`
- `docs/GUNPACK-RECIPE-INTERFACE.md`
- `docs/GUNPACK-RECIPE-TEMPLATE.js`

现有规格对象可配置：

- 口径短名和配方 ID；
- 弹壳、粗制弹头、抛光弹头；
- 底火、装药和序列组装中间物；
- 弹壳/弹头模具类型；
- 材料标签；
- 成品物品和 TaCZ `AmmoId`。

下一步应把 `sequence` 也移入规格对象，至少支持：

- `type`：Create 配方类型，如 `create:deploying`、`create:pressing`、`create:cutting`；
- 输入物品、标签和数量；
- 输出物品、副产物和数量；
- 加工时间；
- 展示名称和中间产物贴图；
- 可选的机器说明字段。

`type` 必须经过允许列表校验。机器说明不能替代配方类型：实际能否由机械手、辊压机或其他方块执行，取决于 Create 和附属模组是否注册了对应配方类型。

## 5. 资源和表现

中间物品的资源放在：

```text
src/kubejs/assets/<namespace>/textures/item/<name>.png
src/kubejs/assets/<namespace>/models/item/<name>.json
src/kubejs/assets/<namespace>/lang/zh_cn.json
```

应支持为以下阶段提供独立表现：

- 空弹壳；
- 粗制弹头；
- 抛光弹头；
- 底火；
- 定量装药；
- 未完成弹药；
- 不同品质的最终弹药。

Kaleidoscope Cookery 的 `finished_texture` 字段可以作为加工中显示贴图的参考，但 Create 序列组装本身仍需通过中间物品的模型/贴图表现加工阶段。

## 6. 品质弹药方案

Kaleidoscope Cookery 的品质系统使用 Data Component 保存品质，并由品质计算器修改成品属性和效果。该思路可以借鉴，但不能直接让 TaCZ 识别其品质组件。

建议分层实现：

### 基础品质

- 减装药：低弹速、低伤害，可能降低后坐力或噪音；
- 标准弹：使用基础口径属性；
- 特种弹头：独立弹头材料和特殊命中效果。

### 技术路线

- 弹速、伤害、穿透等基础弹道数值优先使用不同 `AmmoId`；
- 品质名称、颜色、贴图和配方信息可使用自定义 Data Component 或 `custom_data`；
- 命中后的点燃、减速、流血等效果通过 TaCZ KubeJS 事件或兼容模组实现；
- 若命中事件无法读取弹药自定义数据，则为特殊弹药使用独立 `AmmoId`。

不能假设给 `tacz:ammo` 增加任意字段就会自动改变 TaCZ 弹速或伤害。

## 7. 枪械与配件自动化

弹药链稳定后再开发枪械和配件：

- 以枪械蓝图/配件蓝图作为配方入口；
- 用 Create 序列组装制作枪械部件；
- 由机械手负责逐件装配部件；
- 研究 TaCZ 枪械工作台是否能接受自动输入和输出；
- 若工作台不能被机械手可靠控制，则使用 Create 装配线完成部件，再保留工作台完成最终绑定；
- 通过 TaCZ 原生枪械配方、枪包 `AmmoId`/枪械 ID 和生成的数据文件建立适配层。

枪械和配件的加密枪包内容不应被项目解密、重新分发或打包。项目只应提供公开接口、配方适配和用户本地配置。

## 8. 兼容性与更新策略

部署时只复制 `CreateTacZrecipe` 自己拥有的 KubeJS 脚本、资源和配置，不覆盖未来整合包的其他内容。

整合包更新后应按以下顺序检查：

1. Minecraft、NeoForge、KubeJS、Create、Created Deco、Create Diesel Generators、TaCZ 版本；
2. 材料标签是否仍存在；
3. TaCZ 弹药 ID 和枪包 ID 是否变化；
4. Create 配方类型和 JSON 字段是否变化；
5. 资源命名空间和中间物品 ID 是否仍能加载；
6. 在新副本中进行启动、`/reload`、JEI、机械手和存档测试；
7. 通过部署脚本的依赖检查后再复制到目标实例。

旧世界中的 `lo2900r:*` 物品在命名空间迁移后不会自动变成 `createtaczrecipe:*`。若需要兼容旧存档，应额外编写一次性物品迁移脚本，而不是恢复旧项目命名。

## 9. 测试标准

每新增一种口径或品质，至少测试：

- 启动无脚本错误；
- `/reload` 无配方序列化错误；
- JEI 能显示完整工艺链；
- 机械手能逐件执行每一步；
- 中间物品不会被错误消耗或重复生成；
- 成品拥有正确的 `AmmoId`；
- TaCZ 能装填、射击并消耗该弹药；
- 特殊效果在命中实体和方块时符合预期；
- 退出世界和关闭客户端时无新增崩溃；
- 原始 Mechanomania 实例在未部署本项目时保持可启动。

## 10. 推荐开发顺序

1. 把序列组装步骤完全配置化，并加入类型校验；
2. 将 9mm 配方迁移到新接口并重新测试；
3. 增加标准弹、减装药和一种特种弹头；
4. 验证 TaCZ 命中事件能否读取品质数据；
5. 扩展到其他常用口径；
6. 研究枪械/配件蓝图与 Create 装配；
7. 建立版本依赖报告和自动迁移检查；
8. 最后再考虑 Arcana 或其他枪包的专用适配。
