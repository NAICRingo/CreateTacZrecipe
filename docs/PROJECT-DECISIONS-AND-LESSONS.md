# CreateTacZrecipe 有效决策、经验与剩余工作

更新日期：2026-09-16

本文汇总 CreateTacZrecipe 开发至今已经确认的有效决策、曾遇到的问题、可复用经验和当前剩余工作。它用于后续开发窗口快速恢复上下文，不代替具体接口文档。若本文与早期方案文档冲突，以当前源码、实际测试结果和本文中标记为“当前有效”的决策为准。

## 1. 项目定位

CreateTacZrecipe 是 Minecraft 1.21.1 NeoForge 环境下的 Create 与 TaCZ 配方联动模组。当前主目标是为 TaCZ 弹药建立可在 Create 生产线上执行的自动化生产链，同时保留 TaCZ 原工作台作为手工生产和兼容后备方案。

项目边界：

- 本项目负责弹药配方、中间产物、配置接口、资源表现和兼容逻辑；
- Arcana 的 NeoForge 移植属于独立的 `ArcanaNeoForge` 项目；
- 特殊弹药品质、枪械部件和材料属性属于暂定的 `Tactra` 设计范围，不应阻塞本项目的基础弹药自动化发布；
- 不解密、不修改后重新分发受保护枪包，不复制其他模组源码或素材；
- Tetra、Kaleidoscope、Modular Golems、LO2900、Create Sentry Mechanical Arm 等只作为玩法、数据结构或公开接口参考。

- 实现通用部件、模具、弹壳/弹头压铸、弹头打磨和 Create 序列组装；

- 建立静态验证脚本，当前完整环境可校验28个弹药定义、199条配方和128个物品标签；

- Create Diesel Generators 当前承担模具和压铸功能，因此在当前架构中是必要前置；
- 当前原型、接口、文档、构建和部署流程已经进入 Git 历史。

## 3. 当前有效的依赖结论

### 必要依赖

- Minecraft 1.21.1；
- NeoForge 21.1.248；
- Create 6.0.10；
- KubeJS 2101.7.2；
- TaCZ 1.1.8；
- Create Diesel Generators 1.3.15，当前用于模具、`CDGEvents.molds` 和 `compression_molding`。

### 可选兼容

- Create Deco：不能再影响默认经济平衡；
- 枪包及其他 Create 附属：通过配置和适配目录接入；
- Arcana：属于其他项目，不是 CreateTacZrecipe 前置。

### Create 金属材料确认

Create 6.0.10 本体提供：

- `create:copper_nugget`，位于 `#c:nuggets/copper`；
- `create:brass_nugget`，位于 `#c:nuggets/brass`；
- 铜粒、黄铜粒与对应金属锭均为 9:1 转换；
- 黄铜锭由铜锭和锌锭通过加热搅拌生产。

因此最低前置方案可以直接使用通用铜粒和黄铜粒，无需 Create Deco 硬币。

## 4. 已确认的配方设计决策

### 4.1 使用 TaCZ 原配方作为经济基准

- 默认口径的批量、铜锭、火药和额外材料以 TaCZ 原枪械工作台 JSON 为基准；
- 自动化允许略低于手工材料消耗，以补偿设备、动力、模具和产线建设成本；
- 建议金属节省约 11.1%，火药节省约 4% 至 6%；
- 青金石、烈焰棒、铁粒等特殊材料暂不打折；
- 枪包弹药未取得原始配方前，只能视作临时配置，不能宣称已经平衡。

### 4.2 金属坯方案

直接把硬币替换为锭会令安装和移除 Create Deco 时成本相差约九倍。直接使用 9 个粒进行普通压块又会与 Create 的金属锭配方竞争。因此采用有模具区分的 CDG 压铸：

```text
8 黄铜粒 + 通用金属坯模具
→ CDG 压铸
→ 黄铜弹壳坯 ×1

8 铜粒 + 通用金属坯模具
→ CDG 压铸
→ 铜质弹头坯 ×1
```

- 每份金属坯对应原配方的一锭材料单位，但仅消耗 8 粒；
- 相比 9 粒/锭节省 11.1%；
- 黄铜与铜可以共用一副本项目专用模具，由输入材料决定产物；
- 模具可重复使用，其一次性制作成本不计入每批材料；
- 具体模具制作成本仍待确定。

### 4.3 弹壳与弹头材料分配

- TaCZ 原配方只给出铜锭总量；自动化方案将其拆分为黄铜弹壳坯和铜质弹头坯；
- 保持金属坯总数等于原铜锭数，只有每坯从 9 粒降为 8 粒；
- 这种拆分改变了铜、锌的材料结构，但提高了工艺合理性；
- 12G 原配方必须保持 15 份基础金属和 18 铁粒，不能误写为 5 份金属；
- .50 BMG 的 110 份基础金属拆为 60 弹壳坯和 50 弹头坯；
- `.22 WMR` 原配方产出 100 发，当前实现是 96 发。若保留 96 发，实际每发金属节省约 7.4%，需要明确记录而不是假装完全相等。

### 4.4 底火和火药

- 纯铁板批量压制底火缺乏材料逻辑，应把一部分火药成本转移到底火；
- 轻型、标准、重型三档通用装药不能准确覆盖所有口径，当前各口径火药成本曾出现少 62.5% 到多 150% 的偏差；
- 建议建立细分底火药剂和口径定量装药：

```text
1 火药 → 松散装药 ×24
1 松散装药 → 底火药剂 ×8
1 底火药剂 → 小型枪械底火 ×1
```

- 每个口径的底火与定量装药合计控制在 TaCZ 原火药成本的约 94% 至 96%；
- 原有轻型、标准、重型装药物品 ID 不宜直接删除，以免破坏存档；可以保留为兼容物或不再作为默认序列组装的直接输入；
- 定量装药应按口径区分，避免玩家使用最低成本装药替代高成本口径。

### 4.5 生产过程与 Create 关系

- Create 已有成熟的序列组装和成品控制逻辑，不需要自行重写机械手控制成品；
- 中间产物用于表达加工阶段、平衡批量生产并避免一次机械手操作只能处理一件物品造成的比例问题；
- 12G 应使用独立霰弹流程，包含弹丸/弹托或切割步骤，不应完全套用普通金属弹头流程；
- 注液、切割、鼓风等工艺用于支持配方多样性，而不是为了无意义地拉长所有生产线；
- 工作盆配方竞争可以暂时通过过滤器解决，但长期应通过更明确的输入、模具或独立中间物减少歧义。

## 5. 可配置与兼容策略

- 默认口径由统一目录驱动，不为每种口径复制一整套脚本；
- 配方材料、数量、工序、成品和 `AmmoId` 应通过受校验的数据接口定义；
- 外部枪包可通过 `config/createtaczrecipe` 中的 JSON 增补、覆盖或禁用；
- 中间产物使用本项目命名空间，并允许资源包替换模型和贴图；
- 外部模组的同用途物品通过标签或配置映射接入，不能把某一个附属模组的物品硬编码为唯一材料；
- 添加新枪包不应要求修改 Java 核心；
- 配置错误应跳过单条定义并给出清晰日志，不能令全部口径停止加载；
- 整合包更新时只部署本项目拥有的文件，不覆盖整套 KubeJS、枪包或其他模组配置。

## 6. 测试与工作方式的有效经验

### 6.1 隔离实例的权限边界

- `Mechanomania11120-CreateTacZrecipe-Test` 是专用测试实例，允许大胆部署、替换本项目文件和自动测试；
- 原始 `Mechanomania11120` 实例是保护对象，不应被开发脚本修改；
- 测试结果应区分静态验证、游戏加载、JEI显示、实际流水生产和射击消耗，不能以其中一项代替全部验证。

### 6.2 提高开发效率

- 开发提示词应以阶段目标为主，不重复所有历史约束；
- 在目标范围内应持续执行到构建、部署和验证完成，不能因为非关键检查轻易停止；
- 设计问题在分析窗口讨论，开发窗口负责实现；
- 小改动尽量集中成一批，再做代表性测试，避免每改一个字段都要求人工启动游戏；
- 自动化测试负责语法、JSON、配方数量、ID唯一性、依赖缺失保护和构建；
- 人工测试集中在JEI、流水线、实际成品、TaCZ装填射击和交互表现；
- JEI界面开启时强行退出曾有既有崩溃，不应当阻塞配方开发，除非证明由本项目新增。

### 6.3 遇到异常时的排查顺序

1. 先判断原整合包是否可正常运行；
2. 再检查本项目脚本、物品注册、配方类型和资源；
3. 区分游戏启动、进入世界、打开界面、执行配方和退出阶段；
4. 不因其他模组出现在堆栈中就直接修改它；
5. KubeJS/Rhino 环境不能任意访问 Java 类，必须使用允许的 KubeJS 接口；
6. Gradle 构建成功只证明代码能编译，不证明游戏内功能正确。

## 7. 原创性与发布原则

- 当前源码未发现直接复制 Tetra、Kinetic Pixel、Create Sentry Mechanical Arm、LO2900 或 CDG 实现的证据；
- 使用公开注册名、Recipe Type、事件或数据格式属于接口调用，不等于复制源码；
- `references/` 中的整合包、枪包、TaCZ生成数据和第三方资源不得随正式源码或发布包重新分发；
- 正式公开前必须增加明确的 `LICENSE` 和 `NOTICE`/`CREDITS`；
- 文档应明确说明其他模组只作为设计参考，没有复制或重新分发其代码和资产；
- 最终JAR应检查第三方命名空间、源码、模型和纹理是否被意外打包。

## 8. 已废弃或修正的方案

- 废弃：Create Deco 硬币存在时用硬币、不存在时1:1回退到金属锭。原因是经济成本相差约九倍；
- 废弃：9粒通过普通Create压块生产金属坯。原因是会与9粒合成金属锭竞争；
- 修正：12G不是5铜锭，而是15铜锭、6火药、18铁粒，产出18发；
- 修正：`.22 WMR` 原始产量是100发，当前自动化产量是96发；
- 废弃：用轻/标准/重三档装药直接平衡所有口径。原因是不同口径的实际火药差异过大；
- 暂缓：手持模具直接加工置物台。当前接口不易可靠实现，不阻塞自动化生产；
- 暂缓：品质弹药、枪械部件属性和炮台需求。这些属于后续大版本或Tactra范围；
- 暂缓：服务端整合包导出。当前配方、美术和枪包覆盖尚未达到发布状态。

## 10. 后续版本或独立项目

以下内容不应阻塞第一版弹药自动化闭环：

- 特殊弹药的燃烧、减速、穿甲、曳光等运行时效果；
